# Начальник участка — обзор DEC-025

**Объект:** `ios-research-runtime`  
**Решение:** `CHANGE_COURSE`  
**Здоровье:** `ORANGE`

## Обстановка

Производство сейчас `idle`: активного работника нет. Смена №49 Петровича была закрыта stale-recovery и ждёт независимого ОТК; supervisor-review уже находится в pending queue.

Технический курс по APFS остаётся правильным, но исполнение буксует. Несколько смен подряд runtime теряется после повторной проверки уже локализованных wiring points и до сохранения минимальной target mutation. Это уже управленческая проблема: повторная разведка не добавляет знания и не приближает exact E2E.

## Управленческое решение

Выпустил `DIR-012`, действующую с NEXT_SHIFT. После ОТК следующая смена должна принять существующие decoded NXSB readers и `writeNXEvidence` как проверенную стартовую базу, без нового архитектурного круга сразу сохранить минимальный wiring edit в `main.go`, немедленно сделать checkpoint/heartbeat, затем убрать wrong-layer C# abort в необходимом объёме и пройти обязательные Windows gates/exact E2E.

APFS writer по-прежнему заморожен до причинного structural mismatch. Proof gates и Definition of Done не меняются.

Решение владельца, STOP или перевод объекта не требуются.

**Decision:** `DEC-025`.
