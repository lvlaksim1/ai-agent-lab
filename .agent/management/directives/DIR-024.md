# DIR-024 — PROVE CHECKSUM-SAFE APSB LASTMODTIME WRITE MECHANISM

effective_from: NEXT_SHIFT
status: ACTIVE
source_decision: DEC-060
supersedes: DIR-023

## Direction

1. Preserve the verified shift-96 primitive defect as the starting point: existing `FixedTime` propagation does not assign APSB `LastModTime` / reader `ModificationTime`. Do not retry the ineffective direct FixedTime mutation.
2. Inspect only the minimum pinned go-apfs-v2 serialization/write path needed to answer two questions: where APSB `LastModTime` can be assigned, and where the affected APFS object checksum is regenerated before bytes are persisted.
3. Prefer an existing typed writer/builder field or serialization hook. If none exists, define the smallest bounded implementation that assigns LastModTime before the normal checksum/write stage. Do not post-process serialized APFS bytes unless evidence proves checksum regeneration remains correct.
4. Persist concrete evidence for the chosen mechanism before target mutation: exact code path, assignment point, checksum/write point, and why the mutation cannot leave a stale checksum.
5. Apply only the justified LastModTime preservation change, using authoritative current preimage and SHA/CAS. Immediately checkpoint the exact target commit SHA.
6. Run focused tests, Windows gate, then exact Windows E2E. Consume terminal evidence before any further writer change.
7. Keep XID/checkpoint semantics and `metaCryptoKeyOsVersion` frozen unless the new E2E evidence independently discriminates them.
8. If no checksum-safe assignment path can be established with available evidence, persist the exact missing primitive/evidence and stop that production shift without speculative mutation.

## Success criterion

A checksum/serialization-safe APSB LastModTime assignment mechanism is proven and either implemented as one bounded CAS-safe mutation followed by focused tests -> Windows gate -> exact Windows E2E, or a concrete mechanism-level blocker is persisted without speculative target changes.
