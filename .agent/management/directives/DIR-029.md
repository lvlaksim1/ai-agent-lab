# DIR-029 — LOCALIZE APFS MOUNTROOT ERROR 79 BEFORE MUTATION

object_id: ios-research-runtime
effective_from: NEXT_SHIFT
status: ACTIVE
source_decision: DEC-072
supersedes: DIR-028

## Direction

1. Treat ramdisk packaging size as a closed negative discriminator: exact E2E `35545935392` proved the md0 size is the patched DMG rounded to 512-byte sectors, not a causal truncation/divergence.
2. Do not perform another APFS writer semantic change, KeyOSVersion experiment, XID/checkpoint change, adjacent MetaCrypto mutation, or packaging correction without new discriminating evidence.
3. Add or use the narrowest available **read-only** evidence channel around the APFS mountroot path to identify the first object, lookup, validation or invariant that fails before `apfs_vfsop_mountroot` returns error 79. Prefer existing logs/debug hooks; if insufficient, add bounded diagnostic instrumentation only.
4. Correlate the failure with the rebuilt image's concrete APFS structure. Record exact object/type/address/XID/checksum or equivalent identifiers wherever obtainable. Preserve the landed LastModTime fix and corrected live-volume KeyOSVersion mapping/checksum path.
5. If the first failing invariant identifies a bounded causal defect, apply only the smallest source-preserving correction, then run focused tests → Windows gate → exact Windows E2E and consume terminal evidence in the same live shift.
6. If the available evidence channel cannot distinguish the failing APFS boundary after the evidence-acquisition ladder is exhausted, persist the attempted routes and return to management rather than broadening mutations speculatively.

## Success criterion

Authoritative evidence localizes error 79 to the first concrete APFS object/lookup/validation/invariant that fails, or exhaustively proves the currently obtainable read-only routes cannot discriminate it; any subsequent mutation is tied directly to that evidence and validated through terminal Windows E2E.
