# DIR-028 — TRACE RAMDISK PACKAGING BEFORE FURTHER APFS MUTATION

object_id: ios-research-runtime
effective_from: NEXT_SHIFT
status: ACTIVE
source_decision: DEC-071
supersedes: DIR-027

## Direction

1. Treat the APFS-container-versus-md0 size mismatch localized by exact E2E run 35539990359 as the current discriminating boundary.
2. Do not perform another APFS writer semantic change, KeyOSVersion experiment, XID/checkpoint change, or adjacent MetaCrypto mutation unless new evidence proves that the packaging boundary is not causal.
3. Trace the ramdisk packaging path end-to-end from the produced APFS/container bytes through image assembly to the bytes and size exposed as md0. Record exact sizes, offsets, hashes or other byte-identifying evidence at the narrowest available boundaries.
4. Identify the first boundary where the expected APFS container and the md0-visible image diverge. Prefer read-only instrumentation/evidence over mutation.
5. If a bounded packaging defect is proven, apply only the smallest source-preserving correction, checkpoint the exact target commit SHA, then run focused tests → Windows gate → exact Windows E2E and consume terminal evidence in the same live shift.
6. If packaging is proven byte/size-consistent through md0 while mountroot error 79 remains, persist that negative discriminator and return to management before broadening APFS semantics.

## Success criterion

Authoritative evidence identifies the first exact packaging/visibility divergence between the generated APFS container and md0, or proves that no such divergence exists; any correction is bounded to that demonstrated boundary and is validated through terminal Windows E2E evidence.
