# Смена ios-runtime-release-20260918-002

Статус: **продолжаем**.

Подтверждено по E2E `35294190788`: сбой происходит в одном и том же блоке SPTM. При нормальном вызове адрес назначения `X0` — корректный высокий виртуальный адрес; при аварийном вызове в блок уже приходит `X0=0x00003ef012ed0000`, и первая запись через него вызывает Data Abort. Значит, проблема формируется выше по стеку, а не в самой инструкции записи.

Сделан минимальный диагностический commit `311187181363ed039df28b2e9d99d9d9eda2c38d`: трассировка перенесена на узкое окно вызывающего кода около `0xfffffff0070d7d04`. Проверки и boot-proof не ослаблялись.

Следующий шаг: получить новый Windows E2E artifact, восстановить формирование неправильного `X0` в caller и только после доказательства причины внести корневое исправление.
